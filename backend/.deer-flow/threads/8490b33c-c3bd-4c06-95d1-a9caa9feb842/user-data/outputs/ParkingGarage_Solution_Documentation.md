# 多层停车场PLC控制系统方案

## 1. 需求分析

### 核心需求
- 管理100个停车位，分为两个区域：电梯1负责1-50号车位，电梯2负责51-100号车位
- 检测车辆到达事件，分配相应电梯
- 跟踪电梯当前位置和目标位置
- 实时更新电梯忙闲状态
- 空闲电梯自动扫描并响应新的车辆到达

### 形式化属性要求
1. 电梯不能同时运行
2. 电梯1位置必须在0-50范围内
3. 电梯2位置必须在51-100范围内
4. 电梯1到达目标后必须空闲
5. 电梯2到达目标后必须空闲
6. 电梯不能被分配到同一个车位
7. 电梯1目标必须在0或1-50范围内
8. 电梯2目标必须在0或51-100范围内
9. 忙的电梯必须有有效目标
10. 电梯移动时位置只能变化1个单位

## 2. 架构设计

### 整体架构图

│ NewCarSlot (INT)     │ │ Elevator Positions │ │ Elevator Status  │

### 模块划分
1. **输入处理模块**：HandleNewCar 方法
   - 处理新车辆到达事件
   - 验证车位号有效性
   - 分配相应电梯
   
2. **电梯管理模块**：UpdateElevatorPositions 方法
   - 更新电梯位置
   - 管理电梯移动状态
   - 执行位置范围检查
   - 维护电梯忙闲状态

3. **输出更新模块**：ScanForNewCars 方法
   - 扫描新的车辆到达请求
   - 分配空闲电梯
   - 协调电梯任务

## 3. 功能块设计

### FB_ParkingGarageController
**功能描述**：主功能块，实现整个停车场电梯控制系统

#### 输入参数
| 参数名称 | 类型 | 描述 |
|---------|------|------|
| NewCarSlot | INT | 新到达车辆的目标车位号 (1-100) |

#### 输出参数
| 参数名称 | 类型 | 描述 |
|---------|------|------|
| Elevator1Busy | BOOL | 电梯1忙闲状态 (TRUE=忙, FALSE=闲) |
| Elevator2Busy | BOOL | 电梯2忙闲状态 (TRUE=忙, FALSE=闲) |
| Elevator1Position | INT | 电梯1当前位置 (0-50) |
| Elevator2Position | INT | 电梯2当前位置 (51-100) |

#### 内部变量
| 变量名称 | 类型 | 描述 |
|---------|------|------|
| Elevator1Target | INT | 电梯1目标位置 |
| Elevator2Target | INT | 电梯2目标位置 |
| CarSlots | ARRAY[1..100] OF BOOL | 车位占用状态数组 (TRUE=已占用) |
| CurrentSlot | INT | 循环计数器 |
| Elevator1Moving | BOOL | 电梯1移动状态 |
| Elevator2Moving | BOOL | 电梯2移动状态 |

#### 方法定义

##### HandleNewCar(SlotNumber : INT)
**功能**：处理新车辆到达事件
- 验证车位号有效性
- 检查车位是否已被占用
- 根据车位号分配相应电梯
- 更新车位占用状态

##### UpdateElevatorPositions()
**功能**：更新电梯位置和状态
- 移动电梯（每次1个单位）
- 检查是否到达目标位置
- 更新电梯忙闲状态
- 执行位置范围验证
- 控制电梯返回地面层

##### ScanForNewCars()
**功能**：扫描并响应新的车辆到达
- 检查空闲电梯
- 分配未处理的车辆到达请求
- 协调电梯任务分配

## 4. 数据结构设计

### CarSlots 数组
```
TYPE CarSlots : ARRAY[1..100] OF BOOL;
```
- 索引范围：1-100（对应车位号）
- 值：TRUE=车位已占用，FALSE=车位空闲
- 用途：跟踪所有车位的占用状态

### 电梯状态数据
```
TYPE ElevatorStatus : STRUCT
 Busy : BOOL;
 Position : INT;
 Target : INT;
 Moving : BOOL;
END_STRUCT;
```
- Busy：电梯忙闲状态
- Position：电梯当前位置
- Target：电梯目标位置
- Moving：电梯移动状态

## 5. 实现建议

### 部署建议
1. **周期执行**：建议以100ms周期执行此功能块
2. **输入处理**：NewCarSlot 输入应使用上升沿触发或每次输入后自动复位
3. **监控需求**：建议添加HMI界面监控电梯状态和车位占用情况

### 安全考虑
1. 添加电梯故障检测和处理逻辑
2. 实现紧急停止功能
3. 添加超时处理，防止电梯长时间处于忙状态

### 性能优化
1. 可以优化 ScanForNewCars 方法，使用事件驱动代替周期性扫描
2. 实现电梯任务队列，处理多个车辆到达请求
3. 添加电梯优先级调度逻辑

| 属性编号 | 属性描述 | 实现方式 |
|---------|---------|---------|
| 1 | 电梯不能同时运行 | 通过设计实现，电梯在各自独立区域运行，逻辑上不会冲突 |
| 2 | 电梯1位置必须在0-50范围内 | 在 UpdateElevatorPositions 方法中强制执行范围检查 |
| 3 | 电梯2位置必须在51-100范围内 | 在 UpdateElevatorPositions 方法中强制执行范围检查 |
| 4 | 电梯1到达目标后必须空闲 | 到达目标后自动设置 Busy 为 FALSE |
| 5 | 电梯2到达目标后必须空闲 | 到达目标后自动设置 Busy 为 FALSE |
| 6 | 电梯不能被分配到同一个车位 | 通过车位范围划分（1-50和51-100）实现 |
| 7 | 电梯1目标必须在0或1-50范围内 | 在分配目标时进行范围验证 |
| 8 | 电梯2目标必须在0或51-100范围内 | 在分配目标时进行范围验证 |
| 9 | 忙的电梯必须有有效目标 | 只有在设置有效目标后才会将电梯标记为忙 |
| 10 | 电梯移动时位置只能变化1个单位 | 在 UpdateElevatorPositions 方法中每次只增减1 |
