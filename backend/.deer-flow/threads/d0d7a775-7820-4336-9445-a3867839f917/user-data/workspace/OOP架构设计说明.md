# 电机控制功能块OOP架构设计说明

## 一、整体架构概述

本设计采用基于IEC 61131-3标准的面向对象编程(OOP)架构，通过抽象基类`FB_BaseControl`实现通用控制逻辑，`FB_MotorControl`子类继承并扩展电机特定功能。这种设计模式符合SIL2安全要求，提供了良好的可维护性、可扩展性和代码复用性。

### 1.1 架构层次
```
┌─────────────────┐
│  FB_MotorControl  │
│  (电机控制子类)    │
└─────────────────┘
        ▲
        │ 继承
┌─────────────────┐
│  FB_BaseControl  │
│  (通用控制基类)    │
└─────────────────┘
        ▲
        │ 依赖
┌─────────────────┐
│  数据类型定义      │
│ (DUT_*)         │
└─────────────────┘
```

### 1.2 设计原则
1. **单一职责原则**：基类专注于通用控制逻辑，子类专注于电机特定功能
2. **开闭原则**：通过继承扩展功能，而非修改基类
3. **里氏替换原则**：子类可完全替代基类运行
4. **依赖倒置原则**：高层模块依赖抽象基类，而非具体实现
5. **SIL2安全原则**：故障安全设计、冗余诊断、失效安全输出

## 二、基类FB_BaseControl设计

### 2.1 核心接口
#### 输入接口
- `Enable`: BOOL - 系统使能信号
- `Reset`: BOOL - 故障复位信号
- `EmergencyStop`: BOOL - 紧急停止信号

#### 输出接口
- `Status`: E_ControlStatus - 运行状态
- `FaultCode`: WORD - 当前故障码
- `FaultActive`: BOOL - 故障激活标志
- `RunTime`: UDINT - 累计运行时间(ms)
- `StatusWord`: WORD - 状态字(符合SIL2标准)

### 2.2 核心功能
1. **状态管理**：实现Idle/Running/Fault/Stopped状态机
2. **故障处理**：统一的故障置位、复位和码管理
3. **诊断信息**：运行时间统计、状态字输出
4. **安全联锁**：故障时强制进入安全状态
5. **SIL2合规**：双冗余故障检测、安全状态确认

## 三、子类FB_MotorControl设计

### 3.1 扩展接口
#### 输入接口（继承+扩展）
- `Start`: BOOL - 电机启动命令
- `Stop`: BOOL - 电机停止命令
- `Reverse`: BOOL - 正反转切换
- `SpeedSetpoint`: REAL - 速度设定值(0.0-100.0%)
- `CurrentFeedback`: REAL - 电流反馈值
- `TemperatureFeedback`: REAL - 温度反馈值
- `OvercurrentThreshold`: REAL - 过流阈值
- `OvertemperatureThreshold`: REAL - 过热阈值
- `OverloadTimeThreshold`: UDINT - 过载时间阈值(ms)

#### 输出接口（继承+扩展）
- `MotorRunning`: BOOL - 电机运行状态
- `MotorDirection`: BOOL - 电机方向(正/反)
- `SpeedOutput`: WORD - 模拟量输出(0-27648)
- `FaultHistory`: ARRAY[0..9] OF ST_FaultRecord - 故障历史记录
- `FaultHistoryCount`: BYTE - 故障记录数量

### 3.2 扩展功能
1. **电机控制**：启动/停止、正反转、速度调节
2. **保护功能**：过流、过热、过载、短路保护
3. **诊断系统**：10条故障历史记录、实时状态监控
4. **性能优化**：1ms周期支持、<10ms响应时间
5. **安全设计**：SIL2合规的故障处理逻辑

## 四、安全设计考虑

### 4.1 SIL2合规特性
1. **故障检测**：双通道冗余检测
2. **失效安全**：故障时输出进入安全状态
3. **诊断覆盖**：>90%的故障检测覆盖率
4. **状态反馈**：明确的状态指示和故障代码
5. **手动复位**：故障需要手动复位才能恢复

### 4.2 安全机制
- 紧急停止优先于所有控制命令
- 故障状态锁定，必须手动复位
- 输出信号故障安全确认
- 诊断信息完整性检查

## 五、性能设计考虑

### 5.1 1ms周期优化
1. **简化算法**：避免复杂浮点运算
2. **状态机优化**：减少状态转换判断
3. **数据结构**：使用高效的数组和结构体
4. **内存管理**：避免动态内存分配
5. **并行处理**：将非关键任务移到低优先级任务

### 5.2 <10ms响应时间保障
- 关键控制逻辑在主循环执行
- 故障检测采用硬件中断触发
- 输出信号直接映射，不经过复杂处理

## 六、扩展性设计

### 6.1 功能扩展
- 通过继承基类可以扩展其他设备控制功能
- 子类可重写基类方法实现特定逻辑
- 支持功能模块的动态加载

### 6.2 诊断扩展
- 故障码系统可通过枚举扩展
- 诊断记录可扩展更多字段
- 支持自定义诊断分析工具
